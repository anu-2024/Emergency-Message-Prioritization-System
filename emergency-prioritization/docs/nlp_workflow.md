# NLP Workflow

## 1. Preprocessing (`nlp/preprocessing.py`)
Lowercase → strip URLs/mentions → strip non-alphanumeric punctuation noise
→ (if spaCy available) lemmatize and remove stopwords. Kept conservative:
basic punctuation like `!` and `?` is preserved before lemmatization since
it can correlate with urgency.

## 2. Category classification (`nlp/classifier.py`)
- **Algorithm**: TF-IDF (unigrams+bigrams, max 5000 features) →
  Logistic Regression (`class_weight="balanced"`), with a calibrated
  Linear SVM as a selectable alternative (`--algo svm`).
- **Why classical, not a transformer**: per the SRS's explicit instruction
  to start with a CPU-friendly classical baseline before considering
  heavier models. TF-IDF+LogReg trains in under a second on this dataset
  size and is fully inspectable (`model.coef_` shows which words drive
  each category — useful for the viva).
- **Result on the synthetic dataset**: 100% test accuracy. This is
  expected and **should be reported as inflated** in your write-up — the
  synthetic templates are quite separable by design. Retrain on the real
  Figure Eight dataset (`python -m nlp.classifier --data data/raw/...`
  after preprocessing it into the same `text,category` CSV shape) for a
  realistic, reportable number — expect roughly 75–85% depending on which
  of the 36 original categories you map into your 8-category scheme.

## 3. Urgency detection (`nlp/urgency.py`)
- Same TF-IDF+LogReg architecture, trained on a separate urgency label.
- **Label provenance is disclosed explicitly** because the real dataset
  has no urgency annotations at all:
  - On the synthetic dataset: urgency was assigned by
    `nlp/synthetic_data.py`'s category-conditioned random weights
    (`label_source=synthetic` in the metrics file).
  - On the real dataset: `nlp/urgency.py`'s `heuristic_urgency_label()`
    applies a transparent keyword-tier rule (Critical/High/Medium/Low
    keyword lists, documented in the source) as weak supervision
    (`label_source=heuristic`).
- **Result on the synthetic dataset**: 43% test accuracy on this 4-class
  task — genuinely harder than category classification, because urgency
  was randomized *within* each category rather than purely keyword-driven.
  This is disclosed as an honest limitation, not smoothed over.

## 4. Named Entity Recognition (`nlp/ner.py`)
- **Location**: spaCy's pretrained `en_core_web_sm` statistical NER model
  (GPE/LOC/FAC entity types). This is a genuinely learned model (trained
  by spaCy on OntoNotes), not a lookup table. If spaCy isn't installed, a
  disclosed capitalization-heuristic fallback keeps the pipeline running,
  clearly weaker and labeled as such via the `location_method` field.
- **Assistance type**: a transparent keyword-matching layer (medical,
  food, water, shelter, rescue, fire_response, infrastructure) — this is
  intentionally rule-based, since "type of assistance requested" is a
  task-specific concept general-purpose NER was never trained on. Labeled
  `assistance_method="keyword_matching"` in every output, never presented
  as a learned model.

## 5. Duplicate detection (`nlp/duplicate_detection.py`)
- TF-IDF vectorization of the candidate message plus all previously seen
  messages, cosine similarity, threshold `0.65` (configurable). Chosen
  over embedding models (e.g. Sentence-BERT) for explainability and CPU
  speed, per the SRS's "prefer simple, reliable, explainable" instruction.
- Verified against real injected near-duplicates in the synthetic dataset
  (10 duplicate groups correctly found in a 50-message sample with ~8%
  injected duplicate rate).

## Model artifacts
Trained models are saved to `nlp/artifacts/*.joblib` (gitignored — they're
regenerated by `setup.sh` / the individual training scripts, not committed
